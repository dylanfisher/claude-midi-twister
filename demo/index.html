Twister bench

Chrome only (Web MIDI). Sends straight to the device — no daemon involved, and it works with the daemon dead. Every table here mirrors mft/config.py; a number that's wrong for your unit gets fixed there, not here.

A daemon appears to be running and repainting at 30Hz. It de-duplicates its writes, so anything you send on a channel it isn't currently changing will stick — but the moment that session changes state it will paint over you. For clean results: .venv/bin/python -m mft.daemon --stop.

2 · Ring brightness — channel 6

The focus marker, the RING_CEILING and the focus pulse all depend on this band. If this panel does nothing, none of the three have ever worked and no amount of animation shape will fix them. Ring position is forced to full here so there is something to dim.

Channel 6 carries the indicator tables, and they are channel 3's shifted up by a whole block: 49–56 gate · 57–64 pulse · 65 = brightness 0% · 95 = brightness 100%. An RGB brightness (18–47) sent here lands below the indicator band and does nothing at all — which is what this board did on every ring write for its entire life, and the reason none of the ring features above ever worked. Verify the ceiling by ear rather than by eye: read it as the last value that still changes something, not the first that looks bright.

3 · Target encoder

Slot is also the CC number on every channel: bank N is CC N×16 … N×16+15, so slot and control are the same integer. Selected: slot 0 (bank 1, enc 1)
